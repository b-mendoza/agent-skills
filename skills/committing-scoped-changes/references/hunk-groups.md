# Planning a mixed file

1. Record the full lowercase 40-hex `BASE` from `git rev-parse HEAD` once for the series. From repo root run `python3 -I "$SKILL_DIR/scripts/collect-state.py" hunks 'path'`. Use its numbered changes against HEAD, not Git's diff numbering. If the collector refuses this file as unsplittable, keep it whole. A read failure is `ERROR`.
2. Assign each selected **whole hunk** to one group by reviewer-facing reason. If a hunk itself mixes concerns, keep it whole in one group and explain why, or return `NEEDS_DECISION`. Never synthesize intermediate lines. In `Warnings:` name every unassigned hunk by path and number. If a split file has staged content, warn that its staged content will be replaced by the committed hunks.
3. Order groups by dependency. After `Paths:`, write `Hunks: <BASE> <TOKEN> [<TOKEN> ...]` using the same base throughout. Include one token per split path in this group, in byte order by path. A repeated path needs a token in **every** group containing it. Paths without tokens go whole. A whole-file group has `Hunks: none`.
4. Write each token as `PATH#NEW` or `PATH#NEW+PRIOR` (the last `#` separates the path). NEW lists this group's hunks; PRIOR lists **all** hunks of this path assigned to earlier groups. Omit `+PRIOR` on the first use. Each list is nonempty, strictly increasing positive decimal integers, comma-separated with no leading zeros. The lists are disjoint. For example, `config#2,4` followed by `config#1+2,4` commits 2 and 4 first, then 1.
5. For each group with tokens run `python3 -I "$SKILL_DIR/scripts/collect-state.py" group 'path' ... --hunks 'BASE' 'TOKEN' ...` with every path, base, and token a separate quoted literal. Use its single digest for `Digest:`. It binds the split path's base blob, token, raw worktree bytes and selected blob; it does not bind the moving index. If the collector refuses the selected content as unsplittable, replan the file whole and recompute affected digests. Other digest failures use the planner’s normal error route.
